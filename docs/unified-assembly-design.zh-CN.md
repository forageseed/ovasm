# 统一 Rust 组装引擎：设计方案

状态：共享引擎、U1 相位诊断，以及默认关闭的 U2 路径约束、U3 路径覆盖层、U4 清图审计和一对一重复图解缠已实现，完成下述开发回归。Schoenoplectus 逐记录恢复仍为 0/8，样本恢复目标未通过。默认编码继续使用碱基坐标，HPC 保持实验性，读段纠错未完成。设计目标与已完成验证分别标明，已见样本不算独立验收。

## 目标

用户只运行 `ovasm run`，不预先声明单环、多环或染色体数。普通坐标与同聚物压缩坐标共用一个图引擎、一套原始读段证据、一套清图和路径解析，以及一个 FASTA/GFA 导出流程。HPC 是内部坐标编码，不是第二个组装产品或“多染色体模式”。

一个引擎不等于强制所有技术使用同一种编码。初期保留短读段的碱基坐标；长读段的压缩编码先作为内部实验配置。没有验证依据时，不增加自动猜测、失败后换算法或按组装结果挑最好看的候选。

## 初始问题和证据（2026-10-15 设计时）

源码已有共享基础：`src/hpc.rs` 调用 `assemble::run_backbone_layout`。但是目前只共享骨架，还没有共享完整流程：

- 默认入口具备自动 k、条件纠错和 `add_junctions` 原始读段连接恢复。
- HPC 入口在压缩骨架后恢复 run 长度并直接导出，没有接入上述完整链路，也没有通用的读段穿行解缠。
- HPC 骨架仍调用原清图逻辑；清图发生在完整原始读段路径证据形成前。不能假定默认坐标下的长度、深度与相似度规则在压缩坐标下等价。
- `primary` 选代表路径，不能替代多参考记录恢复，更不能认证物理分子。

2026-10-15 已完成的 Schoenoplectus 全量开发对照：输入 1,044,826 条、16,825,074,678 bp，Rust HPC 的 k1001/s31/min-count80 输出 10 条候选、2,023,910 bp，按既有逐记录协议匹配 0/8，宽松与严格分均失败。保留的旧控制为 8/8，另有 7 条额外序列共 12,862 bp，宽松通过、严格失败。新结果有完整参考片段合并到较长候选、部分参考覆盖不足；尚不能把每项差异归因到某一个清图操作。

正式 Rust 的八条合成序列在默认和 HPC 下均恢复 8/8。这证明默认流程不要求预先选择“多染色体”，不能证明真实复杂样本已通过。

## 统一数据流

`原始读段与质量 → 可逆坐标编码 → 共同图骨架 → 原始读段穿行与来源证据 → 有证据的纠错/清图/重复解析 → 序列共识与原始坐标恢复 → 组件、路径和 FASTA/GFA`

所有阶段保留原始输入身份；参考只进入末端评估，不进入读段分类、补序列、连接选择或参数选择。

### 1. 共用读段和坐标模型

每条读段保留 ID、原始序列、质量、方向、编码序列，以及编码位置到原始区间的单调映射。压缩编码记录每个 run 的原始区间和长度；碱基编码使用恒等映射。反向互补、模糊碱基和读段末端均有明确规则。

共同图类型记录节点、定向边、精确重叠、原始读段穿行及坐标映射。长度必须注明单位：bp、run 或节点数，不允许将现有 bp 参数直接解释成 run。

### 2. 共用骨架，不过早破坏分支

将采样、计数、压缩 unitig、清图计划与 GFA 布局拆开。构图阶段先保留可追溯的候选图；填缺口、移动边界和裁重叠都必须更新坐标映射，不能在证据归属前破坏原坐标。

每次删除或合并形成审计事件，记录原节点/边、原始读段、规则及替代路径。先支持只记录操作而不执行的诊断方式，定位真实损失；不能简单取消所有清图，否则错误和核背景会同时增加。

### 3. 一次原始读段证据服务全流程

用共同读段线程记录方向、节点穿行、进入/离开重复的两侧锚点、间距和歧义。直接相邻边支持与跨整个重复的相位支持分开；多条边分别有读段不等于某条完整路径成立。

先复用现有 `junctions` 的连接恢复和 `read_context` 的完整读段来源证据，再开发尚不存在的通用线程解缠。不能把连接恢复命名为已经完成的通用 unzipping。

核背景判定需要原始完整读段的特异旁侧上下文；局部同源、深度低或 NUMT 候选标签不能单独删组件。无基因真实细胞器组件仍须保留召回检查。

### 4. 共用纠错与共识，但不抹掉真实差异

图拓扑纠错和同聚物长度共识分开。同一原始读段位置在同一共享图坐标最多贡献一次；模糊重复定位不伪装成唯一证据；被读段边界截断的 run 不参与完整长度估计。

当前四舍五入均值只是实验实现。统一版本需要保留 run 长度观测、质量与共穿行关系，检验长度差异是否构成受支持的等位分支，不能把两个真实长度平均成一个不存在的序列。具体估计器在误差模型和对照验证后决定，不先设经验门槛。

### 5. 统一路径输出和完成状态

原始图、处理后的图、读段线程、处理审计及未决路径均保留。最终 GFA 的路径必须能拼写对应 FASTA；导出层不能为了减少记录数强连不同路径，也不能只输出一条代表路径就报告完整多记录恢复。

报告分别给出序列内容、连接支持、重复相位和来源状态。没有独立证据时，`physical_molecule_count=null`，`physical_topology_identified=false`。

### 5a. 线性记录的边界共享重复（规则先于实现，2026-10-17 写定）

问题：`primary` 的线性记录在共享重复处停止（路径的拷贝预算用完，或未放置片段本来就只导出单个片段），重复副本只出现在一条记录里。按记录评估时，另一侧会少掉这段重复；线性 contig 式的表示通常两侧都带重复副本。

规则（只用图结构，不用参考、长度阈值或深度阈值）：对每条**线性**记录的两端分别检查，设末端定向片段为 `e`：

1. `e` 在该方向恰有一个后继 `r`（无歧义延续；有两个或更多后继就不加）；
2. `r` 是共享片段：从 `e` 进入 `r` 的那一侧有至少两个不同的定向前驱（即 `r` 被多条分支共用）；
3. `r` 所属片段不在本记录中（防止环和重复计数）。

满足时在该端追加 `r`，每端至多一个片段，不继续向外延伸。左端在反向图上同样判定，然后把 `flip(r)` 放到最前。环状记录不变；路径选择、拷贝预算、未放置片段的列表都不变，独立的重复记录也保留。追加的片段写在 FASTA 头的 `path=` 和 `flank=` 中，FASTA 仍由该 GFA 路径拼写，所以总长度会增加，且这部分是重复副本。

范围：先作为 `solve primary --boundary-repeats` 的可选项，默认输出逐字节不变；10 个回归输入的成对结果出来后，再决定是否设为默认。Schoenoplectus 全量只用来事后复核，不用来改规则。

**结果（2026-10-17，阴性，规则不采用，代码已移除）。** 实现后两端测试 212 通过。Schoenoplectus 全量在同一 `mt.gfa` 上重新导出：仍为 0/8，额外序列不变（129,762 bp），总长增加 66,216 bp。10 例成对回归中 20 个 GFA 逐字节一致，HPC 路由有 3 例 `primary` 输出改变，没有一例提高记录匹配；Triglochin 线粒体的 1,056 bp 小记录被补成 95,926 bp。原因：被判为“共享”的往往是整条 16–96 kb 的 unitig，而线性参考两端缺的 0.4–0.8 kb 位于片段之间的重叠中（如 `u2+ → u27-` 只有 287 bp 重叠），不是独立片段，所以按片段补的粒度不对。此外，Schoenoplectus 的参考来自 Oatk 数据包，逐记录边界与 Syncasm 的 unitig 断点一致，不能当作独立真值。若以后处理边界重复，需要在连接重叠层面、依据原始读段证据确定重复归属，而不是在导出时追加相邻片段。

### 5b. 引擎融合第二步（2026-10-17）：同一条读段流水线，编码在读入处完成

之前 `run_engine` 只在入口分流，HPC 仍自带一遍“压缩读段 → 写 11.6 GB 中间文件 → 再读回建骨架”。本步把编码放进骨架的读入循环：`run_backbone_layout` 接收 `Coordinates`，读到的每条读段在内存中按该编码转换后进入同一套计数、清图和缺口补救；HPC 不再写 `reads.hpc.fasta`。同时 HPC 与普通路线共用参数规则：`--min-count` 缺省时由骨架按节点深度决定（`--min-count-fraction` 同样可用），`--k` 缺省为 1001（单位为 run）。自动 k 的阶梯只对碱基坐标定义，所以 `--auto-k-depth` 仍不用于压缩编码。

验收口径：（1）固定输入下 HPC 的 GFA 与融合前逐字节相同（纯重构）；（2）自动 min-count 的 HPC 另行对照，报告解析出的值与手动值的差异，不并入（1）；（3）两端测试与 10 例成对回归无退步；（4）JSON 报告字段名不变（OV 适配器读取）。编码仍是显式配置，不做自动选择：10 例里两种编码互有胜负，没有依据。HPC 的读段纠错和通用重复解缠仍未实现，不属于本步。

**结果（2026-10-17，服务器；对照为提交 96347f7 的干净构建，候选为本步源码）。** （1）10 个已招募输入 × 两种编码，参数相同的成对回归中 20 个 GFA 逐字节一致，纯重构成立。（2）候选的压缩路线不传 `--min-count`（由骨架取节点深度的 1/10，下限 3）：解析值与对照使用的碱基路线值不同（例：ZM4 线粒体 53→125，ZM4 质体 323→1009，Schoenoplectus 招募质体 17→69），因为压缩节点深度（k=1001 runs）高于碱基节点深度。10 例中 8 例 GFA 仍逐字节一致；ZM4 线粒体 primary 序列相同（307,026 bp），少 1 条链接；Schoenoplectus 招募质体 unitig 29→23，额外序列 1,467→467 bp，参考覆盖仍为 1.0，仍 0/1。没有一例覆盖或记录损失，但只有这 2 个有变化的例子，且 Schoenoplectus 全量（16.8 Gbp，含大量核背景，手动用了 80）没有用自动值验证，所以自动 min-count 只作为可选省略的参数，不能称为已验证。（3）两端测试 211 通过 / 0 失败。

### 6. 读段穿行解缠（2026-10-18：U1–U4 完成开发回归，Schoenoplectus 恢复目标未通过）

**目的。** 一个重复节点有多个入口和出口时，用整条跨过它的原始读段决定哪个入口与哪个出口相邻，并保留“多种相位同时存在”的事实，而不是靠深度预算猜。不改变默认输出，先只产生诊断。

**现有基础，不重写。** `evidence` 已能给每条链接计算读段支持，并把一条读段的连续联合点串成穿行 `X→S→Y`，在两入口两出口的重复处得到主构型与重组构型及少数派比例（`RepeatPairing`、`minority_share`）；`junctions` 处理短于 k 的反向重复；`read_context` 给核背景的整条读段上下文；`primary` 目前只用深度预算选路径，HPC 路线没有读段穿行证据。统一版本把 `evidence` 作为唯一的读段穿行实现，`primary` 与 `linearize` 都读它的输出，不再各写一套。

**定义。**（1）重复节点：在图上有至少两个不同入口或至少两个不同出口的定向节点，仅按图结构判定，不用长度或深度阈值。（2）相位：一对（入口，出口）。（3）穿行读段：同一条连续比对覆盖重复节点全长，并在入口一侧和出口一侧各有唯一锚点（沿用 `evidence` 的共线单对角线、`min_anchor` 语义）；读段内部含 N 或锚点歧义的不算完整。（4）部分读段：只覆盖入口邻接或只覆盖出口邻接，单独计入“邻接支持”，不当作相位支持。（5）一条读段在同一图坐标最多贡献一次，重叠锚点不重复计数（与 §4 一致）。

**数据结构。** `ReadThread { read, 方向, 访问序列[(节点, 方向, 读段区间)], 歧义标记 }`，只对重复节点汇总，不为每条读段长期保存；`PhaseTable[重复节点] = { 相位 → 完整读段数 + 上限内的见证读段 ID, 入口邻接数, 出口邻接数, 歧义数 }`。流式处理一遍原始读段，相位计数只随图增长，每个相位最多保留 3 个见证 ID。U1 为防止重复输入计数，另保留读段 ID、长度及序列指纹的去重账本，空间随不同 ID 数增长；当前不声称总内存与读段数无关。12–36 GB 笔记本目标需以实测峰值报告。两种编码共用：压缩编码在 run 长度恢复后的碱基 GFA 上计算（与 `restore_junctions` 同位置），所以不需要压缩坐标版本。

**判定（不设拟合阈值）。** 某相位成立 = 其完整读段数不少于该次运行已解析的 `min_count`（与 `junctions` 相同的“最少不同原始读段”规则）。每个重复节点分类为：*已解析*（只有一种配对成立，且无反例读段）、*混合*（多种配对成立，如主构型与重组构型；报告各自读段数与少数派比例，不选一个）、*未解析*（没有任何相位达到 `min_count`，例如重复长于读长；保持原图，不猜）。

U1 另报告 `partial`（已支持配对一对一，但未覆盖全部图入口/出口）和 `conflicted`（一对一的已支持配对之外仍有低于阈值的非零相位）。低于阈值的读段保留原始计数，不因未达到 `min_count` 而把节点称为已解析。任一竞争锚点无法唯一归属时，U1 保守地排除该整条读段的相位贡献，仍保留其无歧义邻接支持。

**U1 的实际接口与边界。** `ovasm check unzip --gfa graph.gfa --reads original.fastq.gz --out-json unzip.json --min-count N`，N 使用该次组装已解析的值。GFA 与路径输出均不改变；报告含逐入口/出口的邻接计数、逐相位读段数、最多 3 个见证 ID，以及上述分类。穿行复用 `evidence` 的两处共线联合点锚点和距离一致性，尚不对重复内部做逐碱基重比对，不能排除所有内部嵌合或认证物理分子。两种编码都在恢复后的碱基 GFA 上使用同一接口。

**输出与使用。**（1）`unzip.json`：每个重复节点的 PhaseTable 与分类；（2）覆盖层 GFA：保留原图，另在 `P` 行中写出已解析相位对应的路径，不删节点、不复制重复；（3）`primary` 的路径扩展改为在“相位被零个完整读段支持”的（入口，出口）对上不通行，其余仍按深度预算；混合节点不强行二选一，两种路径都可导出；（4）`physical_molecule_count` 仍为 null。

**与清图的关系。** 已知问题是清图在读段穿行证据形成前就删除节点。先加“只记录不执行”的清图模式（写出每个将被删的 unitig、规则、其两端的穿行读段数），再比较有无该删除时的 PhaseTable；本设计不改变现有清图规则，也不改“其他细胞器基因整体剔除”的组件规则（Schoenoplectus 的 u17/u4 为实例：`u17-` 有两条出口，完整读段 140 对 125，穿过整条 u17 的 62 对 49，见报告 10-17）。

**行为测试（合成数据，确定性）。**
1. 两入口两出口、主构型与重组构型都有足够读段 → 分类“混合”，两种配对与少数派比例都报告，图不变。
2. 只有一种配对被读段支持 → “已解析”，另一配对零读段不通行。
3. 重复长于所有读段 → “未解析”，不猜，输出与未启用时相同。
4. 反向链读段与正向读段给出相同计数（链对称）。
5. 嵌合读段（前半属一种配对、后半属另一种）→ 记为歧义，不计入任何相位。
6. 读段在重复内部含 N → 不算完整读段。
7. 同一条读段的重叠锚点只计一次。
8. 两个出口共享同一个 44 bp 起点的重复节点（仿 u17：入口 `u0+`/`u1+` 的 48 bp 重叠，出口 `u4-`/`u0+` 共享 44-mer）→ 每个（入口，出口）相位的计数与合成真值一致。
9. 没有任何重复节点达到两相位时，所有现有输出逐字节不变（无行为变更回归）。
10. 碱基编码与压缩编码在同聚物丰富的合成数据上得到同样的 PhaseTable。
11. 读段数放大时相位见证数保持有界；另报告 ID 去重账本的增长与全量峰值内存。总内存不随读段数增长的原提案尚未实现，不能以见证数上限的测试替代。

**真实数据验收。** 先对 Schoenoplectus 招募输入与全量中的 u17 节点计算 PhaseTable，与 10-17 的 minimap2 原型计数（`junction_reads.py`）对照：定义不同（精确 k-mer 锚点对比对），应比较而不强求相等，并解释差异。ZM4（OVASM 与 OATK 的 B/R 分支差异）、Thuidium、Triglochin、Isothecium 的配对回归必须无记录或覆盖损失。已看数据只算开发回归；不按参考或评分结果选择参数；Schoenoplectus 的参考来自 Oatk 输出，不能验证相位，需要独立证据（如 ONT 长读段）时单独说明。

**实施顺序。** U1：只实现读段穿行抽取与 PhaseTable，作为诊断输出，不改图，两种编码都跑，与原型计数对照。U2：`primary` 在可选开关下使用相位约束，默认关闭，成对回归。U3：覆盖层 GFA 的 `P` 行。U4：清图只记录不执行的模式。每一步带测试与成对回归；在“未解析/混合”两类上都没有退步前，不把任何一步设为默认。

**U1 开发验证结果（2026-10-18）。** 两端正式源码测试各 225 通过、0 失败、3 忽略；行为测试包括混合/未解析/低阈值反例、反向链、N、重复 ID 去重、44 bp 出口与 48 bp 入口共享重叠，以及距离不一致的拼接读段。10 个已招募输入 × 两种编码，对照历史构建与本轮正式产品：20/20 GFA 与选定科学字段一致；18 对实际生成的 FASTA 逐字节一致，另 2 路（Schoenoplectus 招募输入的碱基路线，线粒体与质体）双方均未生成序列，不能计为组装成功。20 张候选图另行运行 U1，记录数核对通过，图前后哈希不变。

Schoenoplectus 全量使用同一 ERR8705856 在独立磁盘上的完整 ENA 副本（预存 MD5 `1a77cc7b1df8319bcd86e0d5e95465cc` 核对通过）。将 `ERR8705856.N` 读段 ID 恢复为旧 SRA 导出的序号 N；前 50,000 条 ID、序列与质量逐条一致，11 个原 SRA 分块范围的碱基累计数全部相同，保留全量 1,044,826 条、16,825,074,678 bp。输入已在内存盘的原生 U1 诊断为 55.1 秒、峰值 449 MiB；全部 ID 唯一，图不变。27 个分支节点中：mixed 6、partial 1、conflicted 3、unresolved 17、resolved 0。这是诊断阶段的资源记录，不是端到端组装性能。

u17 的四种正向（入口，出口）完整读段计数为 `(u0-,u0-)=37`、`(u0-,u1-)=18`、`(u4+,u0-)=41`、`(u4+,u1-)=29`。固定 `min_count=80` 下均不成立，节点保持 unresolved。与旧 minimap2 原型的 500 bp 两侧锚点口径比较：原型 134 条，U1 125 条；逐条调用同一正式 U1 核对全部 134 条后，125 条计数与全量完全一致，另外 8 条有竞争锚点歧义、1 条没有通过出口联合点锚点检查。12 条报告内见证均被旧比对支持，进一步检查的全部 125 条相位也均符合原型的近最优完整穿行比对。未为匹配原型更改参数；原型也不是独立的生物学真值。Schoenoplectus 的既有逐记录 0/8 未因此改变，U1 尚不改变路径导出。

**未决风险。** 读长短于重复的样本全部为“未解析”，这是预期结果而不是失败；锚点用精确 k-mer，HiFi 以外的高错误率读段需要重新评估；少数派相位与测序嵌合的区分只靠上面的“嵌合读段不计数”规则，是否足够要在 ONT 数据上检验；该设计没有纠错部分，读段纠错仍是独立工作。

#### U2–U4 与实际拆图接口（2026-10-18，全部默认关闭）

`solve primary --phases unzip.json` 与 `solve linearize --phases unzip.json` 使用同一 `phase::Constraints`。只有每个图入口、出口都至少有一种达到本次 `min_count` 的相位，才将零完整读段的配对设为禁止。尚无足够覆盖的入口/出口不能用零观测否定连接；低于阈值的非零相位保留，不能升级为已支持。检查同时覆盖反向链、圆形路径跨起点的两个相位、线性化的桥间连接、部分路径和切尾后形成的环。

每份新 U1 报告绑定节点名称、序列、定向链接及精确重叠的结构指纹，不依赖深度标签或 GFA 行顺序。该指纹是固定实现的非密码学身份检查；旧报告没有指纹、过滤后换图或序列/拓扑变化时均需重新运行 U1。加载还核对相位阈值标记、邻接计数、分类和完整节点集合，不能只信报告内的 `resolved` 字样。

`check unzip --out-gfa overlay.gfa` 保留所有原 S/L 内容，追加每个已支持相位的 `P` 行及读段计数。P 行表示局部入口—重复—出口证据，不表示整条染色体或全长单倍型。

`check unzip --materialize-gfa split.gfa` 另外生成实际的图：仅把无低阈值反例、覆盖所有端点且一对一配对的 resolved 节点复制成上下文节点；重接其正确方向的入/出边，保留原序列和精确重叠，并按相位支持比例分配深度标签。原节点名写入 OR 标签。mixed、partial、conflicted、unresolved 均不拆；含自身链接的重复需要多次访问证据，也保持原状。图中没有可拆节点时逐字节复制原图。不得把含现有 P/W/C 记录的图悄悄改写丢失路径；有实际拆分时对此类输入报错。原输入文件始终不修改，导出需要新的独立路径。

`assemble graph --cleaning-audit-only` 在 scratch mask 上记录现有清图规则的建议，不执行 unitig 删除；节点计数阈值、边阈值、间隙恢复和序列共识规则不变。FASTA 审计的 action 为 proposed_retained，另写 `.cleaning.json`，记录规则、轮次、坐标单位、深度和对应的保留骨架节点。清图统计在此模式下是建议数，不能解读为实际删除数。HPC 的审计位于 `<out>.rust-hpc/compressed.cleaning.json`，长度单位是 runs；原始读段支持始终在恢复后的 bp 图上计算。

将该 JSON 交给 `check unzip --cleaning-audit-json ...`，可在同一遍原始读段扫描中附加每个保留节点的逐入/出邻接计数和分支相位；不得把多条边计数之和称为不同读段的并集。审计绑定本次恢复后的图；如果原节点已在后续连接阶段改名或拆分，显式报告未在恢复图中找到，不能填零假装已经测量。

这些接口是可组合的显式 CLI 阶段；`assemble` 或 `ovasm run` 不会自动启用相位约束或图拆分。`physical_molecule_count` 仍为 null。两端正式源码的当前测试均为 233 通过、0 失败、3 忽略；包括阈值不足原图不变、低阈值反例保留、双链与跨圆形起点约束、重复节点作为 primary 起点、实际拆图后序列拼接、过期报告拒绝及清图建议保留节点。新增集成测试在每相位阈值 80 下，用 160 条正反链原始合成读段穿过 44/48 bp 共享重叠，验证完整 U1 到节点复制、重接和拼接序列保持；最终服务器产品 SHA-256 与已完成全量/回归的产品完全相同。

**U2–U4 的真实开发验证。** 输入固定为完整 1,044,826 条 / 16,825,074,678 bp；完整 ENA MD5 和规范 FASTQ SHA-256 与 U1 相同，执行前后核对。全量组装固定 k=1001 runs、s=31、min_count=80、8 线程，预先声明原版正常清图、新版正常清图、新版仅审计清图三组，不根据评分改参数。正常组的新旧原图、线粒体图和 primary FASTA 均字节一致。10 输入 × 两种编码的默认回归为 20/20 GFA 一致、18 对实际 FASTA 一致，另两路双方均无序列；启用相位约束后也为 18 对 FASTA 一致、两路均无序列。有参考且有序列的 11 路另行评分，没有记录匹配、覆盖或严格验收退步；其余路线只报告结构/输出一致性，不据此声称准确率通过。无序列不能计为组装成功。

仅审计组记录 245 条清图建议，涉及最终图上 85 个不同节点，全部保留；245 条保留映射记录均附加了原始读段证据，没有映射缺项。同一节点在不同轮次的建议不得重复算作不同节点。原图分支数从正常组的 27 增至 56，完整穿行读段从 30,117 降至 6,879，锚点歧义读段由 24,079 增至 56,384；两张图的分支定义不同，不能把完整穿行总数直接当作灵敏度对比。审计模式没有改善记录恢复，不设为默认。正常组和审计组的 resolved 数均为 0。

正常组线粒体图的五个分支节点均为 unresolved：u15 为 52/67/78/76，u17 为 37/18/41/29，u27 为 4/6/11/9，u30 为 7/7，u55 为 68/71/59/61；都未达到每相位 80。该图没有可据此复制的节点，也没有已支持相位 P 行；拆图导出逐字节保留原图。阈值没有降低，未把 78 视为 80，也未把多个相位的读段数相加通过门槛。

三组全量的 primary，及新版的相位 primary、拆图图上的 primary、相位 linearize 全部仍为 0/8，宽松/严格记录验收均未通过。正常组 primary 25 条、额外 129,762 bp；审计组 primary 36 条、额外 143,622 bp，停止清图没有改善恢复目标。另用现有正式 `unify` 做确定性的零重叠表示诊断，三组同样为 0/8；阴性结果保留，不采用其结果挑参数。

正常组八个参考的最佳单比对身份均为 1.0，跨所有候选的参考合计覆盖最低为 0.999753；单条候选仍有过长延伸或边界重复分配不一致，部分记录的单条参考覆盖不足。合计覆盖不能替代固定的一对一记录协议。约 69 kb 的超出参考序列的来源仍缺独立证据；不能为达到参考记录边界而直接删去它。U2–U4 的工程交付与该样本的恢复失败分别报告。

## 实施顺序与验收

1. **无行为变更的接口整合。** 抽取共同图/读段/坐标模型，保留当前默认输出；现有固定输入的 GFA、FASTA 和科学报告字段对照必须一致。HPC 专有能力如实标为实验。
2. **把默认流程的证据能力接入共同流程。** 恢复原始坐标后先接现有连接恢复、来源上下文与下游解析；用受支持连接、核特异旁侧、歧义重复、无基因组件和反向链测试验证。单独接入口不算完成。
3. **按读段证据审查清图和重复解析。** 对 Schoenoplectus 逐阶段定位：骨架已丢失、清图删除、run 恢复错误、组件排除或路径导出问题，分别修复，禁止按参考补救。通用解缠与 run 等位共识另设行为测试。
4. **现有真实样本成对回归。** 至少包括 Schoenoplectus 全量、ZM4、Thuidium、Isothecium、Triglochin。相同读段和资源口径，记录参数单位差异；保存首轮失败，不按真值选参数、不重试挑结果。已看数据只算开发回归。
5. **满足验收后再统一默认。** 先证明原来通过的内容和受支持连接没有退步，并分别报告逐参考宽松/严格分、额外序列、缺失、时间和峰值内存。没有同个体参考的样本不计准确率。Schoenoplectus 新 HPC 的 0/8 是必须解决的已知退步，旧控制严格失败也必须保留。

所有产品测试绑定两端正式源码；重计算仅在服务器。实验对照与正式验收分开。没有完成以上验证前，不移除可复现的默认实现、不宣称已实现一个经过验证的新默认引擎，也不将历史成绩改记到新实现。
