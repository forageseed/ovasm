# 统一 Rust 组装引擎：设计方案

状态：设计提案，尚未实现或验收。普通入口继续使用现有默认实现；实验 HPC 的结果不算默认实现的验证成绩。

## 目标

用户只运行 `ovasm run`，不预先声明单环、多环或染色体数。普通坐标与同聚物压缩坐标共用一个图引擎、一套原始读段证据、一套清图和路径解析，以及一个 FASTA/GFA 导出流程。HPC 是内部坐标编码，不是第二个组装产品或“多染色体模式”。

一个引擎不等于强制所有技术使用同一种编码。初期保留短读段的碱基坐标；长读段的压缩编码先作为内部实验配置。没有验证依据时，不增加自动猜测、失败后换算法或按组装结果挑最好看的候选。

## 当前问题和证据

源码已有共享基础：`src/hpc.rs` 调用 `assemble::run_backbone_layout`。但是目前只共享骨架，还没有共享完整流程：

- 默认入口具备自动 k、条件纠错和 `add_junctions` 原始读段连接恢复。
- HPC 入口在压缩骨架后恢复 run 长度并直接导出，没有接入上述完整链路，也没有通用的读段穿行解缠。
- HPC 骨架仍调用原清图逻辑；清图发生在完整原始读段路径证据形成前。不能假定默认坐标下的长度、深度与相似度规则在压缩坐标下等价。
- `primary` 选代表路径，不能替代多参考记录恢复，更不能认证物理分子。

2026-10-15 已完成的 Schoenoplectus 全量开发对照：输入 1,044,826 条、16,825,074,678 bp，Rust HPC 的 k1001/s31/min-count80 输出 10 条候选、2,023,910 bp，按既有逐记录协议匹配 0/8，宽松与严格分均失败。保留的旧控制为 8/8，另有 7 条额外序列共 12,862 bp，宽松通过、严格失败。新结果有完整参考片段合并到较长候选、部分参考覆盖不足；尚不能把每项差异归因到某一个清图操作。

正式 Rust 的八条合成序列在默认和 HPC 下均恢复 8/8。这证明默认流程不要求预先选择“多染色体”，不能证明真实复杂样本已通过。

## 统一数据流

`原始读段与质量 → 可逆坐标编码 → 共同图骨架 → 原始读段穿行与来源证据 → 有证据的纠错/清图/重复解析 → 序列共识与原始坐标恢复 → 组件、路径和 FASTA/GFA`

所有阶段保留原始输入身份；参考只进入末端评估，不进入读段分类、补序列、连接选择或参数选择。

### 1. 共用读段和坐标模型

每条读段保留 ID、原始序列、质量、方向、编码序列，以及编码位置到原始区间的单调映射。压缩编码记录每个 run 的原始区间和长度；碱基编码使用恒等映射。反向互补、模糊碱基和读段末端均有明确规则。

共同图类型记录节点、定向边、精确重叠、原始读段穿行及坐标映射。长度必须注明单位：bp、run 或节点数，不允许将现有 bp 参数直接解释成 run。

### 2. 共用骨架，不过早破坏分支

将采样、计数、压缩 unitig、清图计划与 GFA 布局拆开。构图阶段先保留可追溯的候选图；填缺口、移动边界和裁重叠都必须更新坐标映射，不能在证据归属前破坏原坐标。

每次删除或合并形成审计事件，记录原节点/边、原始读段、规则及替代路径。先支持只记录操作而不执行的诊断方式，定位真实损失；不能简单取消所有清图，否则错误和核背景会同时增加。

### 3. 一次原始读段证据服务全流程

用共同读段线程记录方向、节点穿行、进入/离开重复的两侧锚点、间距和歧义。直接相邻边支持与跨整个重复的相位支持分开；多条边分别有读段不等于某条完整路径成立。

先复用现有 `junctions` 的连接恢复和 `read_context` 的完整读段来源证据，再开发尚不存在的通用线程解缠。不能把连接恢复命名为已经完成的通用 unzipping。

核背景判定需要原始完整读段的特异旁侧上下文；局部同源、深度低或 NUMT 候选标签不能单独删组件。无基因真实细胞器组件仍须保留召回检查。

### 4. 共用纠错与共识，但不抹掉真实差异

图拓扑纠错和同聚物长度共识分开。同一原始读段位置在同一共享图坐标最多贡献一次；模糊重复定位不伪装成唯一证据；被读段边界截断的 run 不参与完整长度估计。

当前四舍五入均值只是实验实现。统一版本需要保留 run 长度观测、质量与共穿行关系，检验长度差异是否构成受支持的等位分支，不能把两个真实长度平均成一个不存在的序列。具体估计器在误差模型和对照验证后决定，不先设经验门槛。

### 5. 统一路径输出和完成状态

原始图、处理后的图、读段线程、处理审计及未决路径均保留。最终 GFA 的路径必须能拼写对应 FASTA；导出层不能为了减少记录数强连不同路径，也不能只输出一条代表路径就报告完整多记录恢复。

报告分别给出序列内容、连接支持、重复相位和来源状态。没有独立证据时，`physical_molecule_count=null`，`physical_topology_identified=false`。

### 5a. 线性记录的边界共享重复（规则先于实现，2026-10-17 写定）

问题：`primary` 的线性记录在共享重复处停止（路径的拷贝预算用完，或未放置片段本来就只导出单个片段），重复副本只出现在一条记录里。按记录评估时，另一侧会少掉这段重复；线性 contig 式的表示通常两侧都带重复副本。

规则（只用图结构，不用参考、长度阈值或深度阈值）：对每条**线性**记录的两端分别检查，设末端定向片段为 `e`：

1. `e` 在该方向恰有一个后继 `r`（无歧义延续；有两个或更多后继就不加）；
2. `r` 是共享片段：从 `e` 进入 `r` 的那一侧有至少两个不同的定向前驱（即 `r` 被多条分支共用）；
3. `r` 所属片段不在本记录中（防止环和重复计数）。

满足时在该端追加 `r`，每端至多一个片段，不继续向外延伸。左端在反向图上同样判定，然后把 `flip(r)` 放到最前。环状记录不变；路径选择、拷贝预算、未放置片段的列表都不变，独立的重复记录也保留。追加的片段写在 FASTA 头的 `path=` 和 `flank=` 中，FASTA 仍由该 GFA 路径拼写，所以总长度会增加，且这部分是重复副本。

范围：先作为 `primary --boundary-repeats` 的可选项，默认输出逐字节不变；10 个回归输入的成对结果出来后，再决定是否设为默认。Schoenoplectus 全量只用来事后复核，不用来改规则。

**结果（2026-10-17，阴性，规则不采用，代码已移除）。** 实现后两端测试 212 通过。Schoenoplectus 全量在同一 `mt.gfa` 上重新导出：仍为 0/8，额外序列不变（129,762 bp），总长增加 66,216 bp。10 例成对回归中 20 个 GFA 逐字节一致，HPC 路由有 3 例 `primary` 输出改变，没有一例提高记录匹配；Triglochin 线粒体的 1,056 bp 小记录被补成 95,926 bp。原因：被判为“共享”的往往是整条 16–96 kb 的 unitig，而线性参考两端缺的 0.4–0.8 kb 位于片段之间的重叠中（如 `u2+ → u27-` 只有 287 bp 重叠），不是独立片段，所以按片段补的粒度不对。此外，Schoenoplectus 的参考来自 Oatk 数据包，逐记录边界与 Syncasm 的 unitig 断点一致，不能当作独立真值。若以后处理边界重复，需要在连接重叠层面、依据原始读段证据确定重复归属，而不是在导出时追加相邻片段。

## 实施顺序与验收

1. **无行为变更的接口整合。** 抽取共同图/读段/坐标模型，保留当前默认输出；现有固定输入的 GFA、FASTA 和科学报告字段对照必须一致。HPC 专有能力如实标为实验。
2. **把默认流程的证据能力接入共同流程。** 恢复原始坐标后先接现有连接恢复、来源上下文与下游解析；用受支持连接、核特异旁侧、歧义重复、无基因组件和反向链测试验证。单独接入口不算完成。
3. **按读段证据审查清图和重复解析。** 对 Schoenoplectus 逐阶段定位：骨架已丢失、清图删除、run 恢复错误、组件排除或路径导出问题，分别修复，禁止按参考补救。通用解缠与 run 等位共识另设行为测试。
4. **现有真实样本成对回归。** 至少包括 Schoenoplectus 全量、ZM4、Thuidium、Isothecium、Triglochin。相同读段和资源口径，记录参数单位差异；保存首轮失败，不按真值选参数、不重试挑结果。已看数据只算开发回归。
5. **满足验收后再统一默认。** 先证明原来通过的内容和受支持连接没有退步，并分别报告逐参考宽松/严格分、额外序列、缺失、时间和峰值内存。没有同个体参考的样本不计准确率。Schoenoplectus 新 HPC 的 0/8 是必须解决的已知退步，旧控制严格失败也必须保留。

所有产品测试绑定两端正式源码；重计算仅在服务器。实验对照与正式验收分开。没有完成以上验证前，不移除可复现的默认实现、不宣称已实现一个经过验证的新默认引擎，也不将历史成绩改记到新实现。

## 代码归属

- `src/assemble.rs`：共同骨架与清图阶段接口，拆开坐标布局和不可逆操作。
- `src/hpc.rs`：可逆压缩映射、原始 run 观测和长度恢复，逐步缩为坐标/共识模块。
- `src/junctions.rs`、`src/evidence.rs`、`src/read_context.rs`：共同连接、线程和来源证据。
- `src/linearize.rs`、`src/primary.rs`：统一路径导出，明确代表序列与完整恢复的区别。
- `src/pipeline.rs`、`src/main.rs`：唯一用户流程；旧 `--multichrom-graph` 仅兼容旧调用，不表示用户已知染色体数。

本轮新加的三样本成对实验尚未提交运行；已有 Schoenoplectus 全量实验已终态，原结果保留。先按本设计核对共用接口，再开展有限对照，避免同时冻结两套正在变动的实现。
